# ドキュメント校閲スキル (Proofread Docs)

このスキルは、`docs/` 配下のマークダウンファイルを高品質に校閲・推敲するためのワークフローを定めたものです。

---

## 🔒 基本原則（遵守すべき制約）

1. **主張・事実関係の保持（絶対制約）**:
   - 著者の意見、スタンス、担当実績、経験年数、スキルレベル、数値などの事実関係や主張は**絶対に改変しない**こと。
   - 成果や実績を誇張したり、逆に控えめに書き換えたりしないこと。
2. **特殊タグ・構造の保護**:
   - `<span class="secret-name">...</span>` などの個人情報マスキング用 HTML タグは**絶対に削除・改変しない**こと。
   - Markdown のテーブル構造、リンク、箇条書き、見出し階層、インラインコード（`` `...` ``）を維持すること。
3. **文体・トーンの適切な使い分け**:
   - **自己紹介・職務要約・About Me**: 丁寧な敬体（です・ます調）。
   - **職歴詳細・業務内容・保有スキル**: 簡潔な体言止め・常体（「〜の設計・構築」「〜を担当」「現在に至る」等）。

---

## 📋 校閲ワークフロー

以下の手順に沿って段階的に校閲を実施します。

### ステップ 1: textlint による自動修正の実行
まずは `npm run lint:fix` を実行し、濁点分離の是正や機械的に修正可能な表記ゆれを一括修正します。

```bash
npm run lint:fix
```

### ステップ 2: 文章全体の精読と文脈チェック
対象ファイル（`docs/resume.md`, `docs/cv.md`, `docs/index.md` 等）を精読し、ルールベースの linter では検知しきれない以下のポイントをチェック・改善します。

- **誤字・脱字・スペルミス**:
  - 例: `Mixdコンテンツ` → `Mixedコンテンツ`、`VScode` → `VS Code`、変換ミスなど
- **重複表現・不自然な接続**:
  - 例: `〜と合わせて利用して利用しています` → `〜と合わせて利用しています`
- **読点や文章のつながり**:
  - 主語と述語のねじれ、不自然な助詞の係り受けの改善
- **ビジネス・技術文書としての適切な言葉遣い**:
  - 職務経歴書やポートフォリオとして洗練された、読み手に伝わりやすい表現へのブラッシュアップ

### ステップ 3: 修正の適用
修正対象のファイルを精密に変更します。

### ステップ 4: textlint による最終検証
再度 linter を実行し、textlint のエラーが 0 件であることを確認します。

```bash
npm run lint
```
※ もしエラーが出た場合は該当箇所を修正して再検証します。

### ステップ 5: 変更内容の報告
ユーザーに対して以下の内容を簡潔かつ明確に報告します：
- 修正箇所の一覧（修正前 / 修正後の比較）
- 各修正の理由（誤字修正、重複表現の解消、読みやすさの向上など）
