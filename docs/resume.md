  - 複数AIモデルの統合と最適化: 物件情報抽出（Gemini 2.5 Flash）とブラウザ自動操作（Gemini 2.5 Flash / Pro + Browser Use）という異なるタスクを持つAIを統合。社内運用テストの土台を構築。
- **技術詳細・設計意図**:
  - **Gemini 2.5 Flashの採用理由**: 複数モデルの比較検証において、性能とコストのバランスが最も優れていたため。実際のマイソクを用いた検証では、重要項目である価格情報の抽出ミスが最も少なかった。一方で、当時は目視による定性評価にとどまったため、定量的な評価指標やテストデータを用いた検証体制を設けるべきだった点を教訓・反省点としている。
  - **イベント駆動アーキテクチャの採用理由**: AIによる画像解析・抽出処理は同期的処理ではAPI Gatewayのタイムアウト制限（29秒）に抵触するリスクが高かったため。また、読み取り完了後のブラウザ自動操作など後続タスクへ疎結合にイベントを連携・拡張できるよう、API Gateway + SNS + SQS + Lambdaによる非同期イベント駆動アーキテクチャを採用した。
  - **ブラウザ操作AIエージェントの採用理由**: 抽出データに生じる表記揺れに対し、入力先システムの制約や選択肢の差異を定型スクリプトやAPI連携のみで吸収するのは困難であったため。人間と同様に管理画面のUIをAIエージェントに状況判断させながら操作させ、柔軟に下書きを作成する方針を採用した。社内に知見がない先端領域であったが、一次情報を自ら調査・検証し、自走してシステム統合を実現した。
  - **AgentOps（評価体制）の調査・設計**: システム開発と並行し、AIエージェントの精度を継続評価する仕組みの調査・設計を推進。一次情報やOSSプロジェクトのプラクティスを参考に、実際のマイソクをAIに読み取らせた結果と用意した正解データを照らし合わせて比較・検証する評価フローを策定した。当時は工数の都合により実装まで至らなかったものの設計知見を蓄積でき、今後実務においてもエージェント評価体制の実装に挑戦していきたいと考えている。
